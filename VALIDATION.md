## Known scope and engineering limits

- Current terrain uses a small, fixed-seed sector. No planetary streaming, oceans, orbit, underground or complete weather simulation.
- Meshes are procedural primitive art, not final authored assets. No voice/music track. Notification tone is generated in code and defaults off.
- Host capability file is local-only and never sent to browser code. Local OS user/process isolation, production authentication, penetration testing and a public internet threat model remain outside this prototype's validation.
- Companion and native history/preferences/reports are volatile; server restart clears them. Game survival/inventory/resource state is persisted in the local save.
- Test actor registration is explicitly exposed to approved control devices for the two-client chat test. It must be removed or replaced by real multiplayer identity before production.
- Session revocation does not remove a device's prior screenshots or knowledge. Read-only devices can view game/probe data only after explicit approval.
- Browser foreground polling is tested. Background tab throttling, mobile suspension, Safari autoplay rules and physical phone permissions remain unverified.
- No moderation backend, external credentials, genuine live-service accounts or physical phone testing were available. Independent mock and local work was completed without requesting credentials.
- Installation of engines/SDKs onto C: was avoided. Existing Windows, Git, Node and driver components on C: were reused.

No reliable elapsed-time/token-usage measurement is available. No effort estimate or production-readiness claim is made.

## Terrain normals and tech-cloud sky update

The reported inverted appearance was confirmed numerically: all 21,600 original unindexed terrain normals pointed down. The fix corrects Godot's clockwise triangle winding and supplies smooth, upward height-gradient normals, UVs and tangents. It does not mask the problem with double-sided rendering. Welding produces 3,721 unique terrain vertices. Audit result: **0 downward normals, 0 reversed faces, 0 negative-scale meshes**, minimum normal Y **0.6482**. All 38 resource positions still match the previous saved layout; cosmetic sky changes preserve the legacy random-sequence advance.

The static background and nearby celestial meshes are replaced by a procedural sky shader with atmospheric gradient, two separately drifting cloud layers, softly shaped density fields, segmented ceramic cells and sparse animated conductive seams. Fusion aperture/rings and stars are also procedural sky elements. The directional sun is aligned to the aperture. Terrain/ceramic roughness was increased to avoid blown specular regions after correcting lighting direction, and shadow normal bias was adjusted. Cloud evaluation uses the half-resolution pass; realtime 256px radiance uses a cheaper atmosphere-only path. These are projected sky layers, not raymarched world-space weather volumes.

DX12 captures were inspected on the RTX 4080. A fixed-view sky region changed in **4,414 of 20,069 sampled pixels (22.0%)** between frames three seconds apart, confirming visible animation in that run. The source gameplay smoke test passed after the normal correction, including actual terrain traversal. Capture files are `runtime/sky-01-clouds.png`, `runtime/sky-02-motion.png` and `runtime/sky-03-ground-normals.png`. No new engine, CUDA component or C: installation was introduced. Performance beyond successful runtime rendering has not been benchmarked.

## Abandoned server-case / PCB-world art update

The current direction replaces the outdoor impression with an enormous dusty server-case interior. The enclosure is generated in the sky shader: vented chassis panels, perforation, status indicators and slow fan rotors. Copper paths, vias, solder-mask seams and worn silkscreen are procedural surface shading on the existing terrain, without changing terrain heights or collision. Three articulated copper roots support transistor-package crowns; capacitor growths, loose chip packages and heat-sink silhouettes form the two biomes. Sagging filament webs are actual line geometry. Local suspended dust uses GPU particles with a generated radial texture, not a downloaded image.

The new `world_art.gd` helper uses a separate deterministic RNG; legacy random draws for replaced props are preserved. The normal audit still reports 0 downward normals, 0 reversed faces, 0 negative-scale meshes, and all 38 resource positions matching the earlier save. The gameplay smoke passed after the artwork update. The six-file allowlisted packed build was launched with DX12 on the RTX 4080; actual overview, transistor/web close-up and PCB-ground captures were inspected under `runtime/interior-*.png`. ## Current direction: stacked boards and abstract cable-management sky

This supersedes the heightfield terrain and literal server-ceiling treatment described in the earlier update records. Terrain is now **57 separate PCB slabs**, grouped into shifted stacks, plus **seven convex ramp wedges and seven landing lips**. The 64 box solids and seven ramp meshes contain 852 non-degenerate faces; the geometry audit found **0 reversed faces and 0 negative-scale meshes**. All 38 saved resource X/Z positions match. Visible board edges show alternating laminate/copper strata, and top circuit patterns use board-local coordinates. Heights range from the basal board to 6.75m.

The actual CharacterBody completed every ramp with no jump input: `PCB_RAMP_PASS 0` through `6`, followed by `VELUM_BOARD_TRAVERSAL_PASS`. Gameplay smoke passed hatching, physics movement, gathering, survival drift, growth, save/load and independently recreated board heights. Vegetation/environment props are component-based: transistor trees, capacitors, heat sinks and chip packages plus eleven understory families (resistor, diode, fuse, inductor, LED, crystal, connector, relay, ceramic component, trim pot and IC). Harvestable ceramic/fiber nodes now read as ceramic SMD parts and conductive rings. This is a representative procedural component library, not an exhaustive catalogue of every possible electronic device.

The sky shader now generates abstract sweeping cable bundles, comb/binding patterns, junction nodes and traveling signal pulses in dusty machine mist. The fan/vent enclosure code was removed. This canopy is background art, with no physical overhead cable collision. Native LINK draws the actual board polygons and ramps; the browser map receives and draws the slab layout with the live player/resource state. These map changes do not grant any new companion permissions.

The seven-file packed build was launched and rendered with DX12 on the RTX 4080. ## Graphics, GI choices and native NVIDIA integration

The current pack has eight source files plus an explicit empty exported script-class cache. High/Ultra now support real SDFGI (4/6 GI cascades), world-space volumetric fog with GI injection and shadowed colored spotlights, SSAO, SSIL, SSR, bloom, temporal AA and a 4096px four-split shadow atlas. Mesh GI modes distinguish static world geometry from moving creatures, egg petals, harvested resources and LINK.

Both GI methods are implemented: cascaded SDFGI and a **512 VoxelGI volume with two bounces**. The populated VoxelGI bake contains 20,437,904 cell-data bytes; the serialized engine-specific cache is approximately 66MB on D:. Its bake/load/render passed on the stock DX12 renderer. This is a fixed-volume alternative, not a claim that VoxelGI universally has higher image quality than SDFGI. See GRAPHICS.md for the scope and trade-offs.

Actual graphics-menu tests exercised window size 1600×900, native/fullscreen output, borderless/exclusive modes, native AA/FSR2, automatic display rollback, Ultra's six GI cascades and isolated settings save/load. Release tests use explicit checks for critical rendering/display states. The UI was visually inspected after fixing its anchoring. Fullscreen uses monitor output; internal render scale/upscaling is separately configurable. Per-user settings are stored under runtime, separate from save data.

The official NVIDIA Godot fork was compiled locally from pinned commit `135dff3887a3d2ccf45cafbd9bdffa7b718e1e76` with production Streamline 2.10.0 libraries. Native runtime capability checks report DLSS/FG on the RTX 4080. Successful SR evaluations and SDK-reported extra presentations are counted in the native code. The full Vulkan/SDFGI test produced positive SR and FG counts with SDK status 0; a separate Vulkan/VoxelGI test also produced positive counts. Later verification uses a moving camera to exercise temporal rendering, rather than only a stationary scene. Exact current counts and package hashes are recorded in `build-rtx/validated.json` only after the required test runs pass.

The experimental NVIDIA fork's DX12 full-scene route crashed with access violation inside `nvwgf2umx.dll`; the stock DX12 route passed its GI tests. The validated NVIDIA launch profile therefore uses Vulkan and retains an explicit stock DX12 fallback. No system driver, CUDA toolkit or local AI development service was installed. New source/build dependencies and binaries are on D:. NVIDIA/Microsoft runtime signatures were checked and notices copied. Source changes add counters and disable automatic Streamline runtime downloads. The initial successful engine compile measured 00:09:09.62; this is not a total task duration or a remaining-effort estimate. Token usage remains unavailable.

FG automatically uses Reflex, disables in-game VSync for the tested profile, and pauses during menus, display confirmation and cache preparation. A warm-up precedes temporal-upscaler activation. This is prototype validation on one Windows / RTX 4080 system; no sustained 2× FPS, artifact-free interpolation, all-driver compatibility or hardware path-traced GI is claimed.
